# RAMS — Shared shape

Controls, panels, and surfaces share **18, 26, and 34 px** radii at a 16 px reference root. A semantic layer applies these roles to components, variants, and the viewer. Shape is configured separately from color, typography, density, and motion timing.

## Single source and roles

Edit only `tokens.json/shapeCustomization`, contract `version: 1`. `primitives` contains lengths, `insets` contains spacing, and `roles` expresses function or relationship. Relative values respect the browser root size and text preference; 16 px is a documentation reference, never an imposed root size.

| Role / CSS variable                      | Current definition             | Resolved at 16 px root  | Use                                                  |
| ---------------------------------------- | ------------------------------ | ----------------------- | ----------------------------------------------------- |
| `control` / `--radius-control`           | `r18`: `1.125rem`              | 18 px                   | Buttons, fields, selectors, and tooltips.             |
| `panel` / `--radius-panel`               | `r26`: `1.625rem`              | 26 px                   | Cards, popovers, and menus.                            |
| `surface` / `--radius-surface`           | `r34`: `2.125rem`              | 34 px                   | Dialogs and expanded surfaces.                        |
| `select-panel` / `--radius-select-panel` | `control + .125rem`            | 20 px                   | Selector option container.                            |
| `select-item` / `--radius-select-item`   | `select-panel − menu − border` | 14 px                   | Inner selector option.                                |
| `menu-item` / `--radius-menu-item`       | `panel − menu − border`        | 20 px                   | Inner menu rows and highlights.                       |
| `tab-item` / `--radius-tab-item`         | `control − tabs`               | 15 px                   | Inner tab within its container.                       |
| `indicator` / `--radius-indicator`       | `r5`: `.3125rem`               | 5 px                    | Small indicators, such as checkboxes.                  |
| `inset` / `--radius-inset`               | `r10`: `.625rem`               | 10 px                   | Small details and inset surfaces.                     |
| `pill` / `--radius-pill`                 | `full`: `9999px`               | Capsule                 | Pills; circles retain their own geometry.              |

Current insets are `menu: .3125rem` (5 px at a 16 px root), `border: 1px`, and `tabs: 3px`. Select uses 20 − 5 − 1 = 14 px; the menu uses 26 − 5 − 1 = 20 px; Tabs uses 18 − 3 = 15 px. These are relationships between a container and its interior, not values duplicated in components. Menu and selector padding and Tabs padding use the same insets. Expressions are clamped with `max(0px, calc(...))` where applicable.

Compact, Default, and Wide do not change shape. Shape also stays the same across themes. A change in browser root size does affect `rem` values: for example, `control` resolves to 22.5 px at a 20 px root. Borders and insets expressed in `px` retain their size.

## Generation and consumption

`src/lib/shape.ts` validates and resolves the contract. `scripts/shape.mjs`, invoked by `npm run tokens`, generates:

- `src/baseline/shape.css`: `--radius-value-*` primitives, `--shape-inset-*` spacing, `--radius-*` roles, utilities, and `data-slot` adapters.
- `src/baseline/shape-tokens.ts`: resolved values and the `ShapeRadiusRole` type for TypeScript consumers.
- Foundations generation includes the shape contract in `public/design-system.json`; public exports and the registry are regenerated by their usual scripts.

The `rounded-sm/md/lg/xl/2xl` utilities map to `inset/control/select-panel/panel/surface`. Slot adapters assign roles by function: a dialog needs `surface`, a popover needs `panel`, Select options need `select-item`, and menu rows need `menu-item`. Variants map their radius aliases to the same roles. Do not add a universal `border-radius` rule or edit generated CSS.

For Motion, use `useShapeRadius(role)` from `src/variants/use-radius.ts`: it reads the same CSS role and lets the browser resolve `rem`, `calc()`, and references before returning pixels for numeric interpolation. Its initial value uses generated tokens with a 16 px reference for deterministic hydration; after mounting, it measures the actual root and observes changes to size, attributes, and fonts. Do not introduce alternative radii in `initial`, `animate`, `exit`, or inline styles.

## Change shape

To change the control radius, edit `shapeCustomization.primitives.r18`; `select-panel` and `tab-item` derive from that role. To change panels or surfaces, edit `r26` or `r34`. If inner padding changes, edit the shared inset and verify the container and its highlight together. Do not replace a nested relationship with a duplicated literal.

The contract accepts `rem` and `px` lengths, non-negative primitives and insets, and exactly the ten defined roles. It rejects unknown versions, missing references, cycles, unknown roles, definitions that mix `offset` and `inset`, and inverted hierarchies between surfaces/panels/controls and their interiors. The manifest does not replace visual review of each component.

Circles, pills, open corners on joined controls, drawers with directional corners, and decorative geometry retain their intended shape. Do not turn everything into a rectangle with the same radius or alter paths, icons, or graphics to make their silhouettes uniform. Decorative exceptions and their purpose are listed in `scripts/component-shape-exceptions.json`; reproducible adaptations are defined in the `component-shape-css.json` and `component-shape-motion.json` policies. Review their purpose before expanding any list.

## Discovery and validation

The `shape` field in `/design-system.json` describes the contract for people and agents: `schemaVersion: 1`, `sourceFile: tokens.json`, `editPath: shapeCustomization`, `densityIndependent: true`, ten roles with descriptions, `cssVariable`, `editPath`, `sourcePath`, declared reference, resolved value, and `resolvedValueAt16`, plus insets, adapters, and constraints. This is a local discovery format; it does not claim DTCG conformance, automatic interoperability, or accessibility certification.

After editing, run `npm run foundations:check`, `npm run tokens`, `npm run build`, `npm test`, and relevant browser tests, including `tests/browser/shape.spec.ts`. Verify both themes and all three densities; Select open with its options; menus and submenus; Tabs; portals; joined controls; and radii during Motion open/close. Also test a text root size other than 16 px. Review decorative geometry and the interaction states used by the application; contract validation does not check their visual result.
