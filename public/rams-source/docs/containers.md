# Galleries, panels and notifications

Carousel uses Embla for snapping and dragging. Give the root an accessible name and each item an identifying label, such as its title and position. Compose Content, Item, Previous and Next; controls stay in normal flow so the host does not need outside gutters. `className` and the forwarded ref on Content apply to the moving track. A vertical carousel needs a definite root height.

The focusable root handles its own Left/Right arrows (Up/Down when vertical), Home and End. Keys from nested controls and editable content are left alone. `dir="rtl"` or `opts.direction` sets both the layout and horizontal key direction. Previous/Next consume RAMS Button, reflect actual scroll limits, honor caller `preventDefault`, and jump immediately when reduced motion is enabled. `opts`, `plugins` and `setApi` expose the pinned Embla API; no automatic rotation is introduced. The callback receives undefined on cleanup. Application code using its API must unsubscribe any listeners it adds.

ResizablePanelGroup, ResizablePanel and ResizableHandle use the Group/Panel/Separator API from react-resizable-panels4.14.8. Orientation belongs to Group. Group fills its parent; give that parent definite dimensions or pass an explicit height through Group style. Use explicit percentage strings such as `defaultSize="60%"`; numeric sizes are pixels in this version. The library owns constraints, pointer dragging, keyboard resizing and separator ARIA. `groupRef` and `panelRef` retain their imperative APIs; ordinary forwarded refs and `elementRef` both receive the actual DOM element, with React19 callback cleanup preserved.

The group reserves two spacing units around its layout for the optional grip and focus indicator at the edges. `withHandle` adds a decorative grip; label the separator according to the areas it resizes. Host style can replace that padding, but must retain enough space for the grip and outline. Keep interactive panel contents reachable at small sizes; a local scroll area can be appropriate. Do not remount panel content just to switch orientation.

Toaster styles Sonner with inherited RAMS tokens and fluid control text; it does not introduce a theme provider or duplicate application state. The `theme` prop defaults to `system`; pass the host's current theme when the application has an explicit theme control. All native Toaster options, icons, toastOptions and refs remain available. Import `toast` from `sonner`, and announce success only after the application has actually completed the action. Provide an action such as Undo when the workflow supports it. Color does not replace the message or state icon. Sonner's own reduced-motion behavior is retained.

[Edition Wall](../examples/edition-wall.tsx) demonstrates a real cover selection, resizable inspection areas, a note preserved when layout changes, a local inspection list and an Undo notification that removes the added item. Its artwork and edition data are original. It does not introduce an external service.
